# AI培训智能客服 Vercel 生产化 MVP 设计规格

## 1. 目标与交付口径

本设计将当前本地可演示的 Part 1–5 成果生产化，并完成原 Roadmap 中的 Part 6。
本周交付一个通过 Vercel 稳定访问、使用 Neon PostgreSQL 持久化、能够由管理员和
客服新人真实试用的 `v0.1.0`。

本次唯一明确延期的能力是“真实 AI Provider 与其可信度验收”。情景实战继续使用
明确标识的确定性 Mock Provider，不得在界面、文档或验收结论中将其描述为真实 AI
效果。

正式飞书免登、企业知识引擎、图片 OCR、多模态知识解析、开放式 RAG 和重度游戏化
仍按原 MVP 规格保持在范围外；“除真实 AI Provider 外完成全部计划”指完成
原实施计划的 Part 1–6，不改变原规格已经明确排除的能力。

## 2. 成功标准

`v0.1.0` 只有同时满足以下条件才算完成：

1. Vercel Production 生成长期有效的 `.vercel.app` 访问地址；
2. 管理员和学员均可使用数据库中的正式账号登录；
3. 未登录、学员和管理员路由权限在生产环境正确生效；
4. 活动知识版本、题库、正式题组、练习记录、场景版本、训练会话、消息、报告、
   训练分配和复核记录均写入 Neon；
5. Vercel 重新部署、函数实例重启和页面刷新后数据不丢失；
6. 管理员可查看知识版本、审核题目、管理场景、分配训练、查看学习记录和处理复核；
7. 学员可完成正式知识小测、查看结果和历史、完成 8 个 Mock 场景并查看报告；
8. `pnpm check`、Playwright E2E、数据库迁移验证和生产冒烟测试全部通过；
9. 至少在公司办公网络和一种中国大陆移动网络完成核心路径验收；
10. 真实源文件、本地 artifacts、密钥和测试密码不进入 Git 或 Vercel 构建产物。

## 3. 生产架构

```mermaid
flowchart TB
    USER["客服新人 / 培训管理员"] --> CDN["Vercel CDN与生产域名"]
    CDN --> APP["Next.js 16 App Router"]

    APP --> AUTH["Auth.js Credentials + JWT"]
    APP --> ADMIN["管理端服务"]
    APP --> QUIZ["知识小测服务"]
    APP --> SCENARIO["情景训练服务"]

    AUTH --> DB["Neon PostgreSQL"]
    ADMIN --> DB
    QUIZ --> DB
    SCENARIO --> DB

    LOCAL["本机可信知识源<br/>MD / XLSX"] --> COMPILER["离线知识编译与门禁"]
    COMPILER --> PUBLISHER["受控发布CLI"]
    PUBLISHER --> DB

    SCENARIO --> MOCK["Mock Conversation / Evaluation Provider"]
    REALAI["真实AI Provider"] -.v0.2.0或后续.-> SCENARIO
```

### 3.1 Web 运行时

- Next.js 16 App Router 全栈 TypeScript 单体继续作为唯一 Web 应用；
- Vercel 承载静态资源、Server Components、Route Handlers、Server Actions 和
  Auth.js 请求；
- 不为 MVP 拆分独立前端和 API 服务；
- 生产运行时禁止依赖本地可写文件系统。

### 3.2 数据库

- Neon PostgreSQL 是 `v0.1.0` 的唯一生产事实源；
- 继续使用 Drizzle ORM、现有迁移和约束；
- 数据库 Repository 实现必须覆盖本地 Store 当前承担的全部业务；
- 本地文件 Store 只保留给自动测试和显式本地 Demo，生产代码路径不得调用；
- 数据库写入需要事务、幂等键和账号隔离；
- 部署前在空白 Neon 数据库完整执行迁移和种子，不能依赖开发机历史状态。

### 3.3 认证

- `v0.1.0` 继续使用 Auth.js Credentials；
- 正式管理员和学员账号由数据库种子创建，不开放注册；
- 生产环境强制停用 `LOCAL_TEST_AUTH_ENABLED`；
- 密码只通过受控环境变量输入并以 bcrypt 哈希保存；
- 后续飞书免登只替换 Auth Provider 与企业用户映射，不改变角色和训练数据。

### 3.4 知识发布

- 真实知识源继续保留在本机，不上传 Git 或 Vercel；
- 本地 `knowledge:check` 生成覆盖报告并通过门禁；
- `knowledge:publish:db` 从可信本机直接向 Neon 发布不可变知识版本；
- 相同知识包哈希重复发布保持幂等；
- 冲突知识不得进入正式题目、场景和评分依据；
- Vercel 构建过程不得读取 `TOC售前客服知识库` 或 `artifacts`。

## 4. 生产数据适配范围

### 4.1 知识与题库

数据库适配需要支持：

- 查询活动知识版本与来源覆盖；
- 保存题目草稿、管理员修改和审核记录；
- 统计 40 题审核进度；
- 生成并发布不可变正式题组；
- 读取当前正式题组；
- 防止未审核题目、冲突知识和旧版本混入正式题组。

### 4.2 学习记录

数据库适配需要支持：

- 服务端核验并保存每次小测；
- 按学员隔离查询历史；
- 保存错题 ID、得分、通过线和题组版本；
- 支持错题重练；
- 管理员按学员、状态和时间查看记录。

### 4.3 情景实战

数据库适配需要支持：

- 查询 8 个已发布场景版本；
- 创建并恢复训练会话；
- 原子追加学员和顾客消息；
- 已完成会话禁止继续追加；
- 保存评分维度、风险、置信度、参考回复和来源；
- 生成原场景重练的新会话；
- 按学员隔离会话和报告。

### 4.4 训练分配与复核

Part 6 必须实现原计划中的基础管理闭环：

- 管理员向学员分配知识小测或场景；
- 学员查看待完成与已完成训练；
- 训练结果自动更新分配状态；
- 关键风险、低分、Mock 低置信度或抽样记录进入复核队列；
- 管理员可查看对话与报告、填写批注并标记复核完成；
- 复核动作保留管理员、时间和原始报告引用。

## 5. 管理端范围

`v0.1.0` 管理端包含：

1. **题目审核**：继续使用现有逐题编辑、来源核对、审核和发布；
2. **知识版本**：只读展示活动版本、哈希、来源覆盖、冲突和发布时间；
3. **场景版本**：查看 8 场景、版本、分类、状态、评分权重和来源；
4. **训练分配**：选择学员、训练内容和截止日期，查看完成状态；
5. **学习记录**：按学员、训练类型、通过状态和时间查看；
6. **复核队列**：查看待复核记录、对话、报告并提交管理员结论。

MVP 不增加复杂经营看板、批量组织架构同步、完整 LMS 课程体系和高级权限配置。

## 6. 40 题内容门禁

技术实现不得自动将剩余题目标记为“知识负责人已审核”。

生产发布前必须完成：

1. 每道题核对题干、选项、答案、解释和来源；
2. 40/40 题均有明确审核记录；
3. 正式题组发布后生成不可变版本；
4. 学员端只读取正式题组；
5. 审核人与发布时间进入数据库审计记录。

Codex 可以根据源知识进行一致性检查、发现错误并提出修改建议，但不能冒充业务知识
负责人完成最终内容签字。若本周没有知识负责人完成审核，系统和部署仍可完成，但
`v0.1.0` 只能标记为“技术验收版”，不能标记为“正式培训内容版”。

## 7. Vercel 与 Neon 部署设计

### 7.1 Vercel 项目

- 从私有 GitHub 仓库 `JzzzX/ai-customer-service-training` 导入；
- Production Branch 为 `main`；
- Preview 使用非生产部署，不读取生产外的真实资料文件；
- 使用 Vercel 自动生成的 `.vercel.app` 域名作为本周交付地址；
- 不在本周新增未备案自定义域名；
- 构建命令使用 `pnpm build`，安装使用锁文件；
- Node.js 版本满足项目 `>=20.9.0` 约束。

### 7.2 环境变量

生产至少需要：

- `DATABASE_URL`
- `AUTH_SECRET`
- 正式种子账号所需变量只在受控迁移/种子环境使用

明确禁止：

- `LOCAL_TEST_AUTH_ENABLED=true`
- 将 `.env.local` 上传到 Vercel
- 将 `EDGEONE_API_TOKEN`、Vercel Token 或数据库凭据提交 Git

### 7.3 区域

- 函数运行区域应尽量靠近 Neon 数据库区域；
- 若当前 Vercel 套餐允许且 Neon 位于新加坡，优先实测 `sin1`；
- 不为了“看起来更接近中国”把函数放在与数据库跨洲的区域；
- 最终选择以登录、小测提交、情景消息写入三条真实链路的测量结果为准。

### 7.4 自动部署

- `main` 推送触发 Production 部署；
- 功能分支或 CLI 部署用于 Preview；
- 部署失败不提升为 Production；
- Vercel 构建日志、函数日志和部署 SHA 进入交付记录；
- 生产部署必须指向已经通过完整验证的 Git 提交。

## 8. 错误处理与可运维性

- 页面需要提供数据库不可用、记录不存在、无权限、提交失败和会话已结束状态；
- Server Action 不向客户端暴露连接串、堆栈或内部路径；
- 写操作必须能够安全重试，避免重复发布、重复消息和重复练习记录；
- 生产日志使用会话 ID、用户 ID、题组版本和场景版本定位，不记录密码；
- 数据库迁移在 Production 部署前单独执行，不在每次 Web 请求中自动迁移；
- 保留 Vercel 上一个健康部署作为应用回滚点；
- 破坏性数据库迁移不属于本周 MVP，迁移只允许向前兼容的新增和约束修正。

## 9. 测试与验收

### 9.1 自动测试

必须通过：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm db:check
pnpm test:e2e
pnpm build
```

新增测试至少覆盖：

- Repository 与本地 Store 契约一致性；
- 账号与数据隔离；
- 题目审核和正式发布事务；
- 小测服务端计分和重复提交；
- 情景消息并发/重复写入、刷新恢复和完成锁；
- 分配状态流转；
- 复核队列触发和处理；
- 未登录、学员、管理员路由权限；
- 生产环境不能启用本地测试账号或本地文件 Store。

### 9.2 数据库验收

- 在新建空数据库执行迁移成功；
- 重复执行种子和知识发布保持幂等；
- 活动知识版本唯一；
- 正式题组和场景版本可追溯；
- 重新部署 Vercel 后历史数据仍存在。

### 9.3 生产冒烟

管理员路径：

1. 登录；
2. 查看活动知识版本；
3. 查看并审核题目；
4. 查看场景版本；
5. 分配训练；
6. 查看学员记录；
7. 处理一条复核记录。

学员路径：

1. 登录；
2. 查看分配；
3. 完成一组知识小测；
4. 查看即时反馈、结果和历史；
5. 完成一段情景实战；
6. 刷新恢复；
7. 结束训练、查看报告并重练。

网络验收：

- 公司办公网络完成上述核心路径；
- 至少一种中国大陆移动网络完成登录、小测提交和情景消息发送；
- 记录访问 URL、测试时间、网络、HTTP 错误和主观可用性；
- 若 `.vercel.app` 在交付网络不可稳定访问，项目不宣布“真实可用”，转入备用部署评估。

## 10. 发布与回滚

### 发布

1. 锁定通过验证的 Git SHA；
2. 备份或快照 Neon；
3. 执行数据库迁移；
4. 发布知识版本、正式题组和 8 场景版本；
5. 部署 Vercel Production；
6. 执行生产冒烟和网络验收；
7. 标记 Git tag `v0.1.0`；
8. 在 Roadmap 记录部署 URL、提交 SHA、知识版本、题组版本和验收结果。

### 回滚

- Web 故障：将 Vercel Production 回滚到上一健康部署；
- 数据错误：停止写入，保留审计证据并按备份恢复；
- 内容错误：停用受影响题组或场景版本，发布修正版，不修改已发布不可变版本；
- 网络不可用：保留 Vercel 部署，启动腾讯云香港或备案后的 EdgeOne 方案评估。

## 11. 本周不做

- 真实 AI Conversation/Evaluation Provider；
- AI 可信度指标正式验收；
- 正式飞书免登与组织同步；
- 企业知识引擎实时接入；
- 图片 OCR、多模态知识解析和开放式 RAG；
- 备案域名和 EdgeOne 中国大陆正式部署；
- 完整经营分析、排行榜、积分和证书。

## 12. 最终交付物

- 可访问的 Vercel Production URL；
- Neon 数据库及可复现迁移；
- 数据库化的知识、题库、练习、场景、分配和复核闭环；
- 管理员与学员正式试用账号；
- 40 题审核和发布记录，或明确的“技术验收版”内容限制；
- 8 个明确标识 Mock 的场景；
- 全量自动测试和 Playwright E2E 结果；
- 公司网络与移动网络生产冒烟记录；
- `v0.1.0` Git tag；
- 更新后的规格、实施计划、Roadmap 和 README。
